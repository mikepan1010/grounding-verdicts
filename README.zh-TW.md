# Grounding Verdicts

一個 [Claude Code](https://claude.com/claude-code) skill，用來擋住那種**看起來完全合理、
但其實是錯的**裁決。

**English: [README.md](README.md)**

## 它針對的失敗

Agent 去複核一份舊報告。它查了資料庫。每一個查回來的數字都是對的。它寫下一句很有把握
的結論 —— 而那句結論是錯的，因為那些數字屬於另一個判準，不是它以為自己在驗的那個。

一個真實例子，剝到只剩骨架：

> 狀態表有一個 `watermark_event_id` 欄位。水位停在 87，該月事件流的最新 `event_id` 已到
> 141。結論：「這個月落後 54 個事件，狀態卻還寫 `done` —— 狀態在說謊。」
>
> 三個數字全部正確。這句裁決是錯的。定義「過期」的那段 production 程式碼會先用
> `source_type` 過濾事件，而這 54 筆全屬於一個**被明文排除**的類型，原始碼裡還附了理由
> （把它算進去，這條線 confirm 完會立刻變過期，形成死循環）。照真正的判準算，這個月就是
> `done`，而且 `done` 是對的。

資料從頭到尾都不是問題。**錯的是判準的歸屬。**

這類錯誤很毒，因為**不會有任何紅字**。查詢跑得動、數字加得起來、文字讀起來通順，而結論
自信地錯著。

## 這個 skill 做什麼

它加上一份交付契約。每一條裁決都要填滿五格。填不出來的那格不是跳過 —— 它會把該條裁決
降級成**未驗**。

| 欄 | 要求 | 不接受 |
|---|---|---|
| **裁決** | 仍成立／已推翻／需修正／**未驗** | 省略 |
| **判準出處** | `檔:行` —— **定義**這個判準的 production 程式碼 | 資料表名、欄位名、自己的推論 |
| **判準排除了什麼** | 該判準明文不涵蓋的東西 | 留空（留空＝沒讀過定義） |
| **權威依據** | 哪個 production 呼叫端真的在用它（grep 結果） | 「這張表名字對得上」 |
| **獨立第二法** | 換一條路得到同一個答案 | 同一支查詢再跑一次 |

外加三條硬規則：

1. **權威由呼叫端決定，不由名字決定。** 要說某個東西是「單一來源」或「對照橋」之前，先
   grep 誰在用它。同一個領域常常有好幾張名字相似的表各司其職 —— 而挑錯的那張照樣算得出
   一個漂亮的數字。
2. **「不存在」宣告要窮舉載體。** 寫下「沒有機制／沒有對映／沒有紀錄」之前，四類都要查
   過：欄位、旁掛審計表、事件流、程式碼路徑。少查一類就只能寫「在 ○○ 沒找到」，**不得寫
   「不存在」**。
3. **摘要與內文不一致＝未交付。** 總表、摘要、commit message 都是交付物。內文改對、標題
   留舊值，等於錯的那一版才是別人會看到的。

skill 裡另外列了一串紅旗句（例如「數字變合理了，所以這次對了」—— 合理性不是驗證），以及
一條常設規則：舊報告裡有日期的結論是**假設**，不是事實。

## 有效嗎

是量出來的，不是講出來的。同一份四題考卷、同一個 codebase、同一個唯讀資料庫、各自獨立
作答，**判分規則在跑之前就登記好、事後沒有改動**。

| | 不讀 skill | 先讀 skill |
|---|---|---|
| 逐格答錯 | **8 / 40** | **0 / 40** |
| 至少錯一條的交付物 | **5 / 10** | **0 / 10** |
| 分模型 | Opus 錯 2/5、Fable 錯 3/5 | Opus 0/5、Fable 0/5 |

份數層的 Fisher 精確檢定：單尾 *p* = 0.016、雙尾 *p* = 0.033。

對照組那 8 格錯的不是隨機散落，而是集中成三種形狀：**查錯權威**（3）、**沒讀判準的排除
條款**（2）、**單一探針做不存在宣告**（3）。唯一沒有人答錯的那題是「數一數有幾列」——
單一探針就答得出來。

### 限制照實說

- 這是一份考卷、一個 codebase、每組 *n* = 10。結果層的證據夠強，但這份考卷不是 benchmark。
- **機制沒有被分離出來。** 安慰劑組——prompt 一模一樣，只把規範換成一份同形狀但主題無關
  （文件排版）的規範——在單一模型跑了 5 次，結果是 1/5。三組排下來是 2/5（什麼都不讀）
  → 1/5（安慰劑）→ 0/5（本 skill），**但 n=5 分不出任何差別**：對兩側鄰居的 Fisher 雙尾
  *p* 都是 1.00。「功勞屬於這張檢查表的內容，還是屬於『有規範可讀』這件事」仍未定。
  唯一那次安慰劑失誤剛好踩在規則①（權威）那一格——提示，不是證據。
- 有一份通過的交付物**違反了規則③**（總表與內文的百分比不一致）卻仍照字面過關 —— 這說明
  判分規則對裁決的「權威」那半驗得比「數字」那半嚴。

  ~/.claude/skills/grounding-verdicts
```

裝好之後所有專案都吃得到。`description` 命中你正在做的事時 Claude 會自己載入，也可以直接

```

## 什麼場景該用

當你要寫的那句話是**判準題**的時候：

- 複核一份舊的報告、backlog 或盤點還成不成立。
- 要宣告某個東西不存在 —— 沒有機制、沒有對映、沒有紀錄、沒有呼叫端。
- 要指名權威：「X 是單一來源／是對照橋／是這件事的定義」。
- 要讀一個帶排除條款或門檻的欄位（`watermark`、`status`、`is_active`、白名單）。
- 裁決要寫進留得下來的東西：文件、commit message、報告。

**資料題不要用** —— 幾列、哪一天、測試過不過。單一探針就答得出來，套上去只是變慢。

一句判斷準則：**我要寫的這句話，是資料題還是判準題？** 多少、哪天、什麼值 —— 資料題。
算不算、過不過期、有沒有、誰說了算 —— 判準題。
